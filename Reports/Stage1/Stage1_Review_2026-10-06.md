# Stage1 전체 점검 — 경사·노트 생성·판정

점검일: 2026-10-06 · Unity 2022.3.60f1 · Stage1  
결론: **현재 Stage1은 노트 누락과 경사 구간의 공간 판정 오차를 먼저 수정해야 한다.** 오르막·내리막에서 같은 박자 입력이 같은 등급을 보장하지 않으며, 현재 채보의 홀드 2개는 일반/동굴 배치 모두 생성되지 않는다.

## 1. 이번에 실제로 확인한 것

단순 코드 검토에 더해 Unity 에디터의 실제 지형을 조회하고, 실제 NoteMapPlacer 배치 함수와 JudgeManager 판정 함수를 별도 검증 공간에서 호출했다. 이동 검증은 원본 지형·물리 설정을 복사한 독립적인 Preview PhysicsScene2D에서 0.02초 간격으로 수행했다.

| 검증 | 결과 |
|---|---|
| Stage1 현재 상태 | 편집 모드, Missing Script 0개, 이동 속도 5, 체력 설정 45 |
| 일반 배치 함수 직접 실행 | 채보 92개 중 **32개 생성 / 60개 건너뜀** |
| 동굴 배치 함수 직접 실행 | 같은 채보 92개 중 **46개 생성 / 46개 건너뜀** |
| 예상 좌표와 실제 배치 비교 | 일반 오차 최대 약 0.000001, 동굴 약 0.0000203. 계산과 실제 함수 결과 일치 |
| 현재 채보의 홀드 2개 | 일반·동굴 모두 **0개 생성** |
| 지형 물리 이동 | 일반 구간 이벤트 입구까지 약 38.92초, 자동 점프 9회 모델링 |
| 일반 구간 이벤트 이전 노트 | 대상 41개 중 12개 생성 누락. 생성된 29개 중 4개는 검증 경로의 최소 거리도 Good 범위 밖 |
| 실제 판정 함수 경계 검사 | Perfect 0.2, Great 0.4, Good 0.6 경계가 코드대로 작동 |
| 홀드 시각화 함수 | 평지·오르막·내리막의 시작/끝/몸통 길이·각도 계산은 정상 |
| 원본 보존 확인 | 종료 시 Stage1 dirty=false, 편집 모드, 원래 플레이어 위치 유지, 노트 0개, 배치기 2개, 열린 제품 씬 1개 |

일반/동굴 배치 숫자는 **각 배치 함수를 개별 호출한 결과**다. 실제 한 판에서는 이벤트가 기존 노트를 삭제하고 동굴 채보를 재배치하므로 32+46개를 전체 플레이 노트 수로 단순 합산해서는 안 된다.

이동 결과는 실제 게임을 완주한 기록이 아니다. 원본 콜라이더·Rigidbody2D·중력·속도를 복사한 물리 재현 결과이며, 자동 점프는 복사한 트리거와 플레이어의 겹침으로 모델링했다. 음악·렌더 프레임·실제 키 입력·HP/결과 이동·이벤트 코루틴은 실행하지 않았다. 20ms 표본 사이를 선형 보간하여 최소 거리를 계산했기 때문에 판정 수치에는 표본화와 점프 호출 시점 차이가 있을 수 있다. 도달 가능 등급은 **공간상 최선의 거리 등급**이며 실제 입력 성공률이 아니다.

Unity 문서는 편집 모드의 물리 시뮬레이션에서 런타임 충돌 콜백이 보고되지 않는다고 설명한다. 따라서 이번 점검은 트리거 기반 전체 판정 성공을 주장하지 않는다. [Unity 2022.3 PhysicsScene2D.Simulate](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/PhysicsScene2D.Simulate.html)

## 2. 노트 생성: 발판 레이어가 검색 대상에서 빠져 있다

두 NoteMapPlacer의 groundLayer 값은 64, 즉 Ground 레이어만 포함한다. 그러나 실제 밟을 수 있는 발판 중 일부가 Default 레이어다.

| 지형 | 상태 | 노트 검색 포함 |
|---|---|---|
| Tilemap | Ground, TilemapCollider2D 활성 | 포함 |
| Tilemap_VisualSlope | Ground, EdgeCollider2D 활성 | 포함 |
| Tilemap_Jump | **Default**, CompositeCollider2D 활성 | **제외** |
| Tilempa_Cave1 | Ground, EdgeCollider2D 활성. TilemapCollider2D는 비활성 | 포함 |
| Tilempa_Cave1 (1) | **Default**, TilemapCollider2D 활성 | **제외** |
| Tilempa_Cave1 (2) | 오브젝트 비활성 | 제외 |

일반 구간 이벤트 이전에 누락된 노트는 3~10번, 38~41번이다. 이 중 3~7번, 10번, 39번, 41번의 X 위치에는 전체 레이어 검색으로 Tilemap_Jump 발판이 실제 확인됐다. 현재 Ground 전용 검색에서는 이 발판을 찾지 못한다. 나머지 8·9·38·40번 위치는 해당 X 바로 아래에 발판이 없는 점프 공간으로 확인됐다.

예를 들어 3번 노트는 2.965초, X=18.547에 있다. 현재 검색은 실패하지만 전체 레이어 검색에서는 Default 레이어의 Tilemap_Jump, Y≈-0.375가 잡힌다. 5번 노트도 X=27.293에 발판이 있으나 같은 이유로 생성되지 않는다.

**문제:** FindGroundY가 실패하면 경고를 남긴 뒤 continue하여 노트를 삭제한 것과 같은 결과가 된다. 점프 중 노트는 지면이 없어도 표시할 수 있어야 하지만 현재 방식은 허공에 있는 노트를 생성할 수 없다.

**보완:** 실제 지지 지형의 레이어를 통일하거나 배치기의 지형 마스크를 명시적으로 확장한다. Default 전체를 무작정 포함하면 다른 콜라이더까지 지면으로 선택할 수 있으므로 발판만 공통 지형 레이어로 옮기는 방법이 더 명확하다. 점프 구간은 지면 검색 대신 경로상 목표 위치 또는 별도 높이 데이터를 사용해야 한다. 검증 단계에서는 생성 누락을 조용히 허용하지 말고 해당 노트 번호와 시각을 오류로 표시한다.

## 3. 오르막·내리막: 노트와 판정점의 높이 기준이 다르다

현재 플레이어는 X≈2.31, Y≈-1.51에서 시작한다. 몸체 콜라이더 높이는 2이며, 위/아래 판정점은 몸보다 **X≈1.41 앞**에 있다.

노트 배치는 `초기 판정점 X + createTime × 5`로 X를 구하고, **그 노트 X 아래의 지면**에 시작 시점의 발바닥→판정점 높이를 더한다. 반면 실제 판정점은 **1.41 뒤에 있는 플레이어 몸체의 Y**를 따라간다.

- 오르막: 노트 아래 지면이 플레이어 아래 지면보다 높아 노트가 판정점 위로 벗어날 수 있다.
- 내리막: 노트 아래 지면이 더 낮아 노트가 판정점 아래로 벗어날 수 있다.
- 점프: 노트는 지면 기준으로 고정되어 있지만 판정점은 캐릭터와 함께 공중으로 이동한다.
- 경사 연결부: 캡슐 접촉, 충돌 보정, 기존 수직 속도로 인해 단순 지면 높이와 실제 플레이어 높이가 추가로 달라진다.

경사도를 m이라고 하면 앞선 거리 1.41 때문에 생기는 지면 높이 차이만 대략 `1.41 × m`이다. 캡슐 지지점과 점프 궤적은 여기에 추가된다. 판정은 X 차이만이 아니라 2D 전체 거리를 사용하므로 이 Y 오차가 판정 등급을 직접 바꾼다.

### 일반 구간의 대표 노트

번호는 JSON의 순서를 1부터 센 값이다. ‘최소 거리’는 물리 검증 경로에서 노트와 해당 줄 판정점이 가장 가까워지는 거리다. 최적 시각의 지연은 음악을 실제 재생해 측정한 값이 아니라 채보 시간 대비 공간상 최적 시각의 차이다.

| 노트 | 채보 시각 | 지면 경사 | 최소 거리 | 공간상 최선 등급 | 최적 시각 차이 |
|---:|---:|---:|---:|---|---:|
| 11 | 9.899초 | +45.00° | 0.630 | 판정 범위 밖 | +57ms |
| 22 | 20.309초 | +27.38° | 0.587 | **Good까지만 가능** | +148ms |
| 24 | 21.952초 | +29.88° | 0.002 | Perfect 가능 | +121ms |
| 26 | 23.808초 | +1.07° / 경사 연결부 | 0.372 | Great까지만 가능 | +205ms |
| 30 | 27.200초 | -25.83° | 0.417 | Good까지만 가능 | +196ms |
| 34 | 31.573초 | -26.92° | 0.695 | **판정 범위 밖** | +236ms |
| 36 | 33.259초 | -26.35° | 0.683 | **판정 범위 밖** | +203ms |

14번 노트도 최소 거리 약 0.630으로 범위 밖이었다. 이 노트 바로 아래 지면의 법선은 평지지만 실제 플레이어 궤적과 고정 배치 높이가 맞지 않아 경사·점프 이후 평지 연결부도 함께 확인할 필요가 있다.

이 결과로 “모든 경사 노트가 실패한다”고 판단해서는 안 된다. 24번은 Perfect까지 가능하다. 핵심은 **같은 박자에 입력해도 지형과 실제 이동 경로에 따라 최선의 등급과 최적 입력 시각이 달라진다**는 것이다.

## 4. X 속도를 5로 설정해도 실제 도착 시각이 유지되지 않는다

PlayerMove.FixedUpdate는 매번 rb.velocity.x=5로 설정한다. 그러나 노트 배치는 충돌과 무관하게 항상 `시간×5`로 계산한다. 물리 검증에서 일반 구간의 실제 X는 이 이상적인 위치보다 최대 약 **0.979 뒤**에 있었다. 속도 5 기준 약 196ms에 해당한다.

30번 노트의 채보 시각에 가로 지연은 약 0.978이고, 가장 가까운 판정 시각도 약 196ms 늦었다. 34·36번에서는 가로 지연과 아래쪽 높이 오차가 함께 발생했다. 따라서 이동 스크립트의 ‘항상 같은 속도로 진행하므로 경사에서 일정하다’는 의도만으로 음악 동기화를 보장할 수 없다.

**보완 방향:** 판정은 음악의 논리 시간과 노트 목표 시각의 차이로 계산하고, 캐릭터와 맵의 시각적 이동을 그 시간에서 파생시키는 것이 가장 안정적이다. 지형 이동을 그대로 유지한다면 적어도 노트 높이를 판정점이 실제 지나갈 경로에 맞추고, 충돌에 따른 X 지연을 측정·보정해야 한다. 단순히 Perfect/Good 거리만 넓히면 구간별 공정성 차이가 남는다.

## 5. 판정 함수 자체와 판정 후보 선택

실제 GetJudgeResult를 임시 Note와 Transform에 호출하여 경계를 검사했다.

| 거리 | 실제 반환 |
|---:|---|
| 0.1999 | Perfect |
| 0.2001 | Great |
| 0.3999 | Great |
| 0.4001 | Good |
| 0.5999 | Good |
| 0.6001 | 판정 없음 |
| 0.587567 | Good |
| 0.697073 | 판정 없음 |

분기식 자체는 코드의 기준대로 동작한다. 문제는 **실제 노트 위치가 이 판정 거리 안으로 들어오지 못하는 경우**다.

JudgePoint는 줄당 currentNote 하나를 OnTriggerEnter2D에서 교체한다. 눌렀을 때 currentNote가 있어야 JudgeManager가 판정을 수행하고, 판정하지 못한 Tap은 OnTriggerExit2D에서 Miss가 된다. 따라서 표의 Perfect 가능 노트도 실제 콜라이더 진입·후속 노트 덮어쓰기·프레임 입력을 함께 검증해야 완전한 성공을 보장할 수 있다. 물리 검증의 거리 등급은 이 후보 처리까지 통과했다는 의미가 아니다.

잠재 위험은 다음과 같다.

- 두 노트가 겹치면 나중에 들어온 노트가 currentNote를 덮어쓸 수 있다.
- 홀드를 잡는 중 후속 노트가 진입하면 기존 홀드 참조가 밀릴 수 있다.
- 경사·점프 중 다른 줄의 콜라이더와 먼저 교차하면 원하지 않는 Miss 경로가 생길 수 있다. 이 부분은 실제 충돌 콜백을 이용한 후속 검증이 필요하다.
- Miss가 음악 시각의 만료가 아니라 공간 콜라이더 이탈에 의존한다.

줄별 시간순 후보 목록, 진행 중 홀드의 독립 참조, 한 노트 한 번만 처리되는 상태가 필요하다. 이 변경은 노트 높이와 시간 기준을 정리한 뒤 진행하는 것이 좋다.

## 6. 홀드: 시각 계산은 정상, 현재 채보에서는 생성되지 않는다

현재 notedata.json의 홀드는 두 개이며 둘 다 아래 줄, 길이 1.5초다.

| 노트 | 시각 | 일반 배치 X | 동굴 재배치 X | 결과 |
|---:|---:|---:|---:|---|
| 56 | 55.019초 | 278.813 | 484.003 | 양쪽 모두 지면 검색 실패로 생성 안 됨 |
| 70 | 69.461초 | 351.027 | 556.217 | 양쪽 모두 지면 검색 실패로 생성 안 됨 |

일반 배치기의 Raycast는 Y=20에서 50만큼 내려가므로 **Y=-30보다 아래는 검색하지 못한다.** 일반 배치 X=278/351의 동굴 지형은 더 깊어서 빠진다. 동굴 배치기는 충분히 깊게 검색하지만 두 홀드의 재배치 X는 Ground 경로 범위를 벗어나며, 484 부근의 추가 발판도 Default 레이어라 선택되지 않는다.

HoldNoteVisual.SetHoldPoints는 실제 프리팹으로 별도 검사했다. 길이 7.5의 평지와 Y±4의 경사에서 시작/끝 위치가 일치했고, 경사 몸통 길이 8.5와 각도 ±28.07°도 정상 계산됐다. 루트 판정 콜라이더 크기는 0.64×0.64로 유지되며 긴 몸통 전체를 판정 콜라이더로 만드는 구조는 아니다.

다만 홀드 몸통과 효과는 시작~끝을 직선으로 잇는다. 중간에 봉우리·단차가 있는 지형은 그 곡선을 따르지 않는다. JudgeManager는 시작 판정 등급을 저장하지 않고 길이를 채우면 항상 Perfect를 주며, 두 줄 홀드 효과도 공용 변수 하나를 쓴다. **현재는 홀드가 생성되지 않으므로 경사에서 홀드 완주가 정상인지 검증할 수 있는 실제 채보 상태가 아니다.** 생성 문제를 고친 뒤 시작/유지/해제·두 줄 동시 홀드를 검증해야 한다.

## 8. 수정 우선순위

1. **생성 누락 제거:** 점프 발판·동굴 후반의 레이어와 지형 마스크를 통일한다. 점프 공간용 노트 높이/경로를 따로 제공한다. 모든 노트에 생성 결과를 확인한다.
2. **Stage1 데이터 연결:** 실제 음악과 선택 화면 곡을 맞추고, 일반/동굴 각각의 채보·시작 시각을 명시한다. 92개짜리 일반 채보를 동굴에서 재사용하는 의도가 없다면 연결을 수정한다.
3. **경사 판정 공정성:** 앞선 판정점과 플레이어 몸의 높이 기준을 맞추고, 판정을 시간 기준으로 전환한다. X 속도 재설정만으로 싱크를 보장하지 않는다.
4. **홀드 검증 가능하게 만들기:** 두 홀드를 실제 진행 구간에 배치하고, 시작 등급·유지 시간·해제·동시 홀드 정책을 정리한다.
5. **종료·일시정지:** 정상 완주 조건, 이벤트 상태, Pause 상태의 입력 차단을 정리한다.

우선 22·30·34·36번을 기준 노트로 삼아, 평지와 동일한 박자 입력이 동일한 등급을 받을 수 있도록 확인하는 것이 좋다. 입력 창을 넓히는 것만으로 수정 완료를 판단하지 않는다.

## 9. 수정 후 통과해야 할 조건

- 의도된 일반 구간 노트와 동굴 구간 노트가 100% 생성되고 누락 번호가 없다.
- 의도된 허공/점프 노트도 생성되며 플레이어가 접근할 수 있는 위치에 있다.
- 오르막·내리막·연결부에서도 동일한 시간 오차가 같은 등급으로 판정된다.
- 22·30·34·36번에서 목표 박자 입력을 실제 게임 키 입력으로 검증한다.
- 홀드 두 개가 생성되고, 길이 유지·중간 해제·일시정지 복귀가 일관되게 처리된다.
- 이벤트 종료 후 다음 구간의 음악·채보·캐릭터 위치가 같은 시간 원점을 사용한다.
- 노트 판정 수, Miss 수, 미처리 노트 수가 채보 총계와 일치한다.
- 정상 완주로 자동 결과 이동하고 재시도해도 이전 상태가 남지 않는다.
- 30/60/120fps와 반복 플레이에서 경사·점프 후 시간 오차가 누적되지 않는다.
