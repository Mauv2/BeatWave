# Stage3 코드 검토 및 플레이 영상 참고 보고서

작성일: 2026-10-09 (한국 시간)

## 1. 검토 범위와 결론

현재 저장된 Stage3 씬, 런타임 스크립트 5개, 에디터 생성·검증 코드 4개, 공용 판정·음악·일시정지 코드, 채보 및 기존 검증 기록을 확인했다. 코드와 씬은 수정하지 않았다. Unity 실행 및 검증 재실행은 하지 않았으며, 아래 실행 결과는 저장된 기존 기록을 인용한 것이다.

현재 Stage3는 **Stage1의 입력·판정·점수·UI를 재사용하고, 음악 시간에 따라 캐릭터 경로와 무대 연출을 진행하는 스테이지**다. 별도로 남아 있는 `Stage3Director`의 독립 판정 구현은 현재 Stage3 씬에 연결되어 있지 않다.

핵심 확인 사항은 다음과 같다.

- 현재 채보는 탭 100개와 홀드 5개이며, 씬의 Mash 3개까지 총 108개 판정이다.
- 현재 씬의 입력은 W/S다. 이전 독립 구현의 D/F 조작 설명을 현재 동작에 적용하면 안 된다.
- 이동·점프·붕괴·상층 이동은 시간 기반이다. Mash 실패에도 경로 전환은 진행된다.
- 현재 씬과 맞지 않는 이전 검증 코드 및 기록이 남아 있다.
- 영상에서 파악한 원작의 규칙과 BeatWave의 구현은 구분해야 한다.

## 2. 현재 실행 구조

| 구성 | 역할 | 확인 근거 |
|---|---|---|
| `Stage3Gameplay` | 채보 생성, 음악 시작, 캐릭터·판정점 이동, 카메라, 정상 종료 요청 | Stage3 씬에 해당 스크립트 GUID가 연결됨 |
| `RhythmClock` | DSP 기반 음악 시간, 예약 재생, 메뉴·흐름 일시정지 | 일반 판정과 Stage3 연출이 같은 시계를 참조 |
| `JudgeManager` | W/S 입력, 탭·홀드 판정, 점수·콤보·HP, 결과 저장 | Stage1의 공용 컴포넌트 재사용 |
| `Stage3Route` | 구간별 위치·방향·곡 종료 시각 | `Stage3Session.cs` 안에 정의되지만 독립 판정 클래스와 별개로 사용 |
| `Stage3MashGate` | 연타 입력·타격 효과·구간 종료 시 1회 판정 | 일반 Mash처럼 음악을 멈추지 않음 |
| `Stage3Transitions` | 발판 붕괴, 파편, 이동 장치, 피날레, 카메라 집중 | 세 게이트의 음악 시각에 연동 |
| `PauseManager` | ESC, 이어하기, 재시작, 곡 선택, 타이틀 이동 | 공용 메뉴 재사용 |

시작 순서는 `Awake`에서 실제 음원 길이와 참조를 준비하고, `Start`에서 일반 노트 전체를 생성·등록한 뒤 두 프레임을 기다려 `BeginSong`을 호출하는 방식이다. 음원은 DSP 시각에 0.1초 뒤 예약 재생한다.

일반 노트는 음악 시간에 대응하는 경로 위치에 미리 놓는다. `NoteMove`를 비활성화하고 플레이어와 카메라가 이동하므로, 별도의 노트 이동 속도로 박자를 맞추는 구조가 아니다. 플레이어 Rigidbody2D의 물리 시뮬레이션은 꺼져 있고 위치를 직접 설정한다. 발판 충돌체가 존재하더라도 실제 주행은 물리적인 접지·중력 계산으로 이루어지지 않는다.

## 3. 조작과 판정

### 현재 씬의 규칙

- W는 위쪽, S는 아래쪽 노트다. 홀드는 해당 키를 끝까지 유지한다.
- lane 0은 아래쪽, lane 1은 위쪽으로 변환한다.
- Perfect는 오차 40ms 이하, Great는 80ms 이하, Good은 120ms 이하다.
- 점수는 각각 100/80/50점이며 Miss는 0점이다. 전부 Perfect일 때 총 10,800점이다.
- Miss마다 콤보가 초기화되고 HP가 1 감소한다. 현재 저장된 씬의 최대 HP는 45이며 공용 코드의 기본값 10과 다르다. 성공으로 HP를 회복하는 코드는 없다.
- 정확도는 처리된 판정의 가중 점수 비율이다. S/A/B/C/D 경계는 95/85/70/50%다.
- HP가 0이면 공용 판정기가 즉시 결과 저장을 요청한다. 따라서 정상 완주는 곡 끝까지 기다리지만 게임오버는 일찍 종료될 수 있다.

정상 종료는 음악 종료, 일반 노트 미처리 없음, 모든 Mash 처리 완료를 모두 만족해야 한다. 그 뒤 공용 결과 저장과 페이드가 실행되므로 결과 씬 전환에는 페이드 시간이 추가될 수 있다.

### Mash 규칙

| 게이트 | 입력 구간 | 내부 필요 횟수 | 후속 연출 |
|---|---|---:|---|
| Fracture | 17.423~19.792초 | 8 | 발판 붕괴와 지하 낙하 |
| Astral lift | 34.792~37.160초 | 10 | 상층으로 이동 |
| Last Wish | 50.810~52.610초 | 8 | 피날레 도약·파동 |

구간 안에서 W와 S의 KeyDown을 각각 받으므로 동시에 누르면 2회 입력으로 계산될 수 있다. 목표 횟수 달성 후에도 입력과 타격 효과가 계속 발생한다. 화면에는 `MASH W / S`만 표시하며 횟수나 완료 안내는 표시하지 않는다.

판정은 목표 달성 순간이 아니라 고정된 구간 종료 시각에 발생한다. 성공은 Perfect 1회, 실패는 Miss 1회이며 이후 이동은 계속된다. 이벤트 노트는 일반 판정기에 등록하지 않고 `ReportEventJudge`로 결과만 전달하기 때문에 공용 Mash의 음악 정지 처리와 분리된다.

## 4. 이동과 화면 연출

경로는 총 20개 구간이다. 지상 이동 13개(평지 6·오르막 4·내리막 3), 점프 1개, Mash 정지 3개, 붕괴·상층 이동·피날레 각 1개로 구성된다. 현재 모든 구간의 x 좌표는 유지되거나 증가하며 왼쪽 이동은 없다.

| 시각 | 진행 |
|---|---|
| 0~12.687초 | 지상 평지·경사 이동 |
| 12.687~17.423초 | 시소 점프와 상단 경사 |
| 17.423~19.792초 | 첫 Mash |
| 19.792~22.160초 | 붕괴·낙하 |
| 22.160~34.792초 | 지하 이동 |
| 34.792~37.160초 | 두 번째 Mash |
| 37.160~39.529초 | 상층 이동 |
| 39.529~50.810초 | 상층 경사·평지 |
| 50.810~52.610초 | 마지막 Mash |
| 52.610~53.160초 | 피날레 도약과 음악 종료 |

일반 점프는 포물선 보간이며 붕괴는 아래 방향 가속 형태의 보간이다. 시소 기울기 역시 고정 발사 시각에 따라 계산된다. 노트 성공 여부가 점프 경로를 바꾸지는 않는다.

카메라는 경로의 0.35초 뒤 위치를 미리 보고 부드럽게 추적한다. 일반 구간 크기는 6.6, 공중 구간은 8.4이며 Mash에는 3.9까지 확대한다. 배경은 화면을 덮도록 크기를 조절하고 지하 레이어를 페이드하며, 곡 진행에 따라 밤색에서 새벽색으로 변한다. 첫 게이트 종료 후 발판 5조각과 파편 24개가 떨어지고 발판 충돌체가 꺼진다.

## 5. 데이터와 생성 코드

`LastWishChart.json`은 152 BPM, offset 0.055초, 일반 노트 105개를 담는다. 정확히 같은 시각의 복수 노트는 현재 0개지만, 홀드 중 반대 레인 탭은 존재한다. 마지막 일반 노트는 50.1866초다.

채보의 duration은 53.093515초이고, 기존 기록의 실제 Unity 음원 길이는 53.160초다. 약 66.5ms 차이가 있다. 현재 이동 종료는 채보 duration 대신 실제 `AudioClip.length`를 사용하므로 이 차이 때문에 곡이 조기 종료되는 구조는 아니다. BPM·offset 메타데이터 역시 런타임에서 노트 시각을 다시 계산하지 않으며 경로 박자는 코드에 별도로 정의되어 있다.

`Stage3SceneBuilder`는 Stage1 씬을 복제하고 UI·플레이어·판정·메뉴를 남긴 다음 Stage3 배경·발판·경로·Mash를 만든다. 곡 선택용 MusicData와 빌드 씬 목록도 갱신한다. 저장 전 기존 Stage3 씬을 Reports에 백업한다. 현재 보고서 작성에서는 생성 명령을 실행하지 않았다.

## 6. 검토 중 확인한 정리 필요 사항

### 현재 구현과 이전 구현의 혼재

`Stage3Director`와 `Stage3Session`의 독립 판정 클래스는 D/F 입력, 백만점 점수, 다른 판정 창과 HP 회복을 사용한다. 현재 씬의 W/S·공용 판정 규칙과 다르다. 단, 같은 파일에 있는 `Stage3Route`와 `Stage3Chart`는 현재 구현에서도 사용하므로 파일 전체를 불필요한 코드로 판단하면 안 된다. `Stage3Drawing`도 씬 생성 코드가 사용한다.

### 이전 검증 코드가 현재 씬과 불일치

`Stage3Validation`은 135노트·8홀드·점프 6개·왼쪽 이동을 기대하고, 씬에서 `Stage3Director`를 찾는다. 현재 씬에는 해당 컴포넌트가 없어 마지막 씬 참조 검사 이후 NullReferenceException이 발생할 수 있다. `Stage3PlayValidation`도 같은 이전 컴포넌트를 요구하므로 현재 씬에서 실행하면 시작 단계에서 예외가 발생한다.

현재 검증 대상은 `Stage3Acceptance`다. `Reports/Stage3-acceptance.txt`의 135노트 기록은 이전 버전이며, 현재 구조에 맞는 기록은 `Reports/Stage3-transitions-validation.txt`다.

### 최신 검증도 실제 키보드 플레이 전체를 증명하지 않음

Acceptance는 일반 판정기의 Update를 끄고 합성 입력을 보낸다. 홀드 완료는 private `Complete`를 리플렉션으로 호출한다. 실제 키 유지·조기 해제, W/S 동시 입력, 체감 조작감은 이 기록만으로 확인되지 않는다.

### 씬 생성 재현성

생성기는 Stage1의 공용 컴포넌트 값을 복제한다. 따라서 현재 Stage3의 HP 45 등은 생성기 자체에서 명시적으로 고정한 설정이 아니다. Stage1 설정이 바뀐 뒤 재생성하면 Stage3 판정·체력 설정도 달라질 수 있다.

## 7. 기존 검증 결과와 이번 검토의 한계

저장된 최신 전환 검증 기록에는 UI·프리팹 재사용, 경로 연속성, Mash 성공·실패, 목표 초과 입력, 음악 연속 재생, ESC, 재시작 초기화, 결과·곡 선택·타이틀 이동의 PASS가 기록되어 있다. 108개 판정 처리 중 에디터 합성 입력 지연에 의한 Miss는 1개, 오디오와 DSP 시계 차이는 최대 134.7ms로 기록되어 있다.

이 수치는 이전 실행 기록이며 이번에 다시 측정하지 않았다. 특히 150ms 미만이라는 기존 테스트 기준은 가장 좁은 Perfect 판정 창 40ms보다 크므로, 이 PASS만으로 음악과 입력의 체감 동기화가 충분하다고 결론 내릴 수 없다.

학습한 핵심은 음악 입력을 캐릭터의 공간 이동과 무대 사건에 결합하고, 공연 사이에 탐색·대화·결과를 이어 붙이는 흐름이다. 현재 Stage3의 공통점은 공간에 배치된 노트, 시간 기반 이동, 집중 카메라와 무대 전환이다. 차이는 현재 채보의 동일 시각 동시 노트 부재, 왼쪽 이동·무대 회전 부재, 수집에 따른 추가 열람 체계 부재다. 참고 방향은 전환 뒤 다음 판정 지점을 미리 보여주고 홀드 가독성을 유지하는 것이다. 영상만으로 성공 입력이 점프나 무대 장치를 직접 작동시킨다고 단정하지 않는다.
