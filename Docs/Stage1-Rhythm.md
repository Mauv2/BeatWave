# Stage1 음악 채보 보정

## 현재 적용 상태 — 2026-10-24

기존 `Tools/build_stage1_chart.py`, `NoteMapPlacer`, `Stage1RhythmAcceptance`를 활용해 동굴 초반 채보를 수정했다. 새 스크립트는 추가하지 않았다.

- 낙하 중 음악은 계속 흐른다. 동굴 도착 예상은 53.178초, 이번 실제 재생 경로 시작은 53.175초였다.
- 전환 중 지나가는 50.243초·50.684초 탭과 51.108초 홀드를 제거했다. 53.703초 탭은 기존 음악 분석 어택인 54.596723초로 옮겼다.
- 일반 노트 102개, 홀드 7개, 고정 이벤트 8개. 첫 노트까지 실제 검사에서 1.293초의 준비 시간을 확보했다.
- 초반 구간만 재적용: `python Tools/build_stage1_chart.py --cave-entry-only`. 전체 재생성에도 같은 보정이 적용된다.
- 전체 자동 판정에서 110개 모두 완료, Miss 0. 첫 노트 준비 시간, 도착 카메라, 음악의 연속 재생과 볼륨 복원은 통과했다.
- 전체 검사는 아직 모두 통과하지 않는다. 연속 음악 전환 이후 경로와 기존 후반 채보의 관계에서 곡 끝 공중 위치, 홀드 선 편차, 점프 어택 정렬, 종결 카메라 상태·줌, 전체 노트 사전 노출 검사가 실패했다. 초반 노트 수정과 별도로 남은 결과이며 `Reports/Stage1-rhythm-validation.txt`를 참고한다.

아래는 기존 작업 기록으로, 현재 노트 개수와 전환 동작은 위 내용을 따른다.

Stage1에 실제 연결된 `Nientum Fortune Waltz (mp3cut.net).mp3`를 유지한다. Unity에서 읽은 길이는 101.6163초다. 지상, 고정 이벤트, 동굴이 같은 음원의 시간축을 사용하며, 낙하 연출 중에는 기존 방식대로 음악 시간을 보존한다.

## 채보

- `Assets/notedata JSON/Stage1Notes.json`: 일반 노트 105개, 그중 Hold 8개. `noteType`은 0=위(W), 1=아래(S), `noteKind`는 0=Tap, 1=Hold다.
- `Assets/notedata JSON/Stage1Timing.json`: 고정 이벤트 Tap 8개, 구간 전환 시각, 분석한 어택 시각. 고정 이벤트 스포너는 Tap만 생성한다.
- 초반 피아노는 여유 있는 간격, 편성이 두꺼워지는 구간은 응답 노트를 추가했다. 쉼표와 이벤트 경계에는 일반 노트를 배치하지 않는다.
- 분석용 기준 펄스는 138.5 BPM이지만 고정 BPM에 기계적으로 양자화하지 않는다. 스윙과 연주 타이밍을 반영하도록 국소 위상과 실제 어택을 사용한다.
- 외부 MP3 디코더의 패딩 차이가 판정 오차로 이어지지 않도록 **Unity가 임포트한 PCM**을 분석한다. 첫 노트는 1.202438초다.
- 기존 수동 채보 `Assets/notedata JSON/notedata.json`은 다른 씬에서도 참조하므로 보존했다. Stage1의 두 NoteMapPlacer에는 새 JSON TextAsset을 직접 연결해 빌드에도 포함한다.

## 이동과 전환

- 38.633005초에 고정 이벤트 진입, 40.734410~48.513095초에 이벤트 판정, 49.378039초 부근에서 낙하 전환 후 동굴 재개.
- 이벤트는 시작 프레임으로부터의 상대 시간이 아닌 음악의 절대 시간으로 판정한다.
- 고정 이벤트 종료 후 같은 곡의 잔향 재생을 낙하·암전·동굴 화면 복귀 전체에 걸쳐 줄인다. 동굴이 보이면 추가 대기 없이 보존한 동굴 구간의 음악과 노트를 함께 재개한다. 별도 `Nientum Stage1-2.mp3`로 전환하지 않는다.
- 전환용 소리는 재개 음원이 실제로 시작될 때까지 낮은 볼륨으로 유지하고, 1초 동안 교차 페이드한 뒤 제거한다. 낙하 중 일시정지는 전환용 소리와 페이드도 함께 멈춘다.
- 이동 경로를 마지막 노트+3초 대신 실제 AudioClip 끝까지 생성한다.
- 동굴 시작 x=207.50에서 곡 끝 x≈468.7까지 기존 타일맵이 충분히 이어지므로 타일 복제/맵 연장은 필요하지 않다.
- 월드 좌표로 정의된 초반 시소 경로와 6.18만큼 옮겨져 있던 발판 부모 좌표를 일치시켰다.
- Hold는 직선 경사 또는 평지에 배치해 표시선과 실제 이동 경로가 일치하도록 했다.

## 재생성 및 검증

1. Stage1을 열고 `BeatWave > Stage1 > Inspect Rhythm Layout`으로 임포트 PCM을 Temp 폴더에 추출한다.
2. numpy/scipy를 사용할 수 있는 Python으로 `Tools/build_stage1_chart.py`를 실행한다.
3. Unity 에셋 새로고침 후 `BeatWave > Stage1 > Apply Music Chart`로 씬에 반영한다.
4. `BeatWave > Stage1 > Validate Full Music Playback`은 실제 101.62초 음악과 이벤트/낙하를 재생하며 판정, 동굴 재개, 일시정지, 최종 결과, 경로와 롱노트 위치를 검사한다.

동굴 오디오 설정만 다시 적용하려면 `BeatWave > Stage1 > Apply Cave Audio Transition`을 사용한다. 전체 재생 검증은 낙하 중 AudioSource 출력, 페이드 지속, 전환 중 일시정지, 원래 음원 재개와 재개 후 오디오/노트 시간 동기화도 검사한다.

검증 기록은 `Reports/Stage1-rhythm-validation.txt`, 실행 화면은 `Docs/Preview/Stage1-Rhythm/`에 저장된다. 입력은 기존 판정 API를 호출하는 자동 입력이며, Hold 종료와 이벤트 판정은 내부 완료 API를 사용한다. 실제 키보드의 연속 누름 감각은 자동 검증에 포함되지 않는다.

최종 전체 재생 검증: 일반 105개와 이벤트 8개 모두 판정, Miss 0, 101.616초 이후 결과 화면 도달. 동굴 재개 49.386초, 일시정지 시 음악·위치 동시 정지, 곡 끝 지형 접지와 Hold 경로 일치 확인. Unity 콘솔 오류·경고 0건.
