# Stage1 템포 기반 게임 속도 (2026-10-16)

원곡의 피치와 재생 속도, 노트 판정 시각은 유지한다. 지상에서 경로를 통과하는 속도와 달리기 애니메이션의 주기를 음악에 맞춘다.

## 음악 분석

- `Temp/Stage1-imported-audio.f32`의 Unity 임포트 PCM을 사용한다.
- 기존 채보의 기준 펄스 138.5 BPM에서 국소 위상을 추적한다. 이번 프로필의 국소 분석 펄스는 약 137.86~139.04 BPM이다. 스윙이 있는 연주를 일정 BPM으로 다시 양자화하지 않는다.
- 2.6초 구간의 음량 에너지와 박자 위상을 이용해 지상 이동의 가감속을 만든다. 음악 자체의 속도를 조작하지 않는다.
- 실행용 데이터는 `Assets/notedata JSON/Stage1Tempo.json`. 노트 JSON을 덮어쓰지 않는 `Tools/build_stage1_tempo.py`로 생성하며 Python과 NumPy가 필요하다.

## 이동과 애니메이션

- Player의 `Stage1TempoMotion`이 공용 `RhythmPath` 생성 마지막 단계에서 지상 구간의 진행 시간을 조정한다. 해당 컴포넌트가 없는 Stage2·3에는 적용되지 않는다.
- 점프 전체와 홀드 전체는 보호한다. 각 구간의 시작과 끝을 고정하여 이벤트 진입, 동굴 재개, 곡 종료를 유지한다.
- 박자와 강약을 반영하되 경계에서 조정량을 부드럽게 0으로 되돌린다. 플레이어와 노트는 같은 조정 경로를 사용한다.
- 진행 시간 배율의 허용 범위는 0.72~1.28이다. 현재 실제 적용 범위는 지상 0.875~1.123, 동굴 0.859~1.144이다. 기존 경사·점프 시간 조정 위에 적용되는 비율이며, 월드 좌표 속도를 직접 제한하는 값은 아니다.
- `pacingStrength`는 0~1이며 기본값은 1이다. 0이면 지상 경로 가감속을 끈다.
- `Assets/Stage1/Animation/Stage1Tempo.controller`는 기존 컨트롤러의 Stage1 전용 복사본이다. `run` 상태에만 `Stage1RunTempo` 배율을 연결한다. 0.5초 달리기 클립의 한 주기를 분석 펄스 한 박에 맞추므로 재생 배율은 약 1.15이다. 피격·상호작용·비행 상태의 속도는 그대로다.

## 재적용과 확인

1. 필요하면 기존 `Inspect Rhythm Layout`으로 현재 Unity PCM을 추출한다.
2. `python Tools/build_stage1_tempo.py`로 프로필을 재생성한다.
3. `BeatWave > Stage1 > Apply Music Tempo Pacing`으로 Stage1 바인딩을 저장한다.
4. `Validate Tempo Pacing`으로 경계·점프·홀드 보존과 경로 연속성, Stage1 전용 애니메이션 설정을 검사한다.
5. `Validate Full Music Playback`으로 전체 곡 판정과 음악·이동·카메라·메뉴 동작을 검사한다.

검사 기록은 `Reports/Stage1-tempo-validation.txt`와 `Reports/Stage1-rhythm-validation.txt`에 저장한다. 자동 입력과 내부 홀드 완료 API를 사용하므로 실제 키보드 체감은 별도 플레이 확인이 필요하다.

## 검증 결과

- 경로 및 설정 검사 16개, 전체 곡 재생 검사 45개 통과.
- 일반 노트 105개와 고정 이벤트 노트 8개 완료, Miss 0. 홀드 8개와 점프 경로 보존.
- 전체 재생 중 14,379회 확인에서 원곡 피치 1, 실시간 배율 1, 템포에 맞는 달리기 배율 유지.
- 동굴 전환 중에도 달리기 전용 배율을 갱신해, 이동 재개 순간 기본 배율로 돌아가지 않도록 처리.
