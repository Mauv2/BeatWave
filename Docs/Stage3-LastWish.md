# Stage3 — Last Wish / 장면 다양성 개정

## 실행

`Assets/Scenes/Stage3.unity`에서 Play 또는 곡 선택 화면의 세 번째 곡.
W: 위 노트, S: 아래 노트. 홀드는 같은 키를 유지. Mash는 W/S 반복 입력. ESC: 일시정지 메뉴.

원본 음원 168.996712초, 152 BPM / 위상 0.014초. 일반 274개(홀드 16개 포함)와 연타 3개, 총 277개 판정. 역주행 시작과 복귀 시점의 노트를 하나씩 비우고, 첫 붕괴·낙하 구간의 노트 5개를 덜어 전환을 읽을 시간을 확보했다.

## 장면 구성

| 시간 | 무대와 이동 |
|---|---|
| 0–18.96초 | 달빛 회랑. 기존 석조 교량과 매달린 달 장식. |
| 18.96–44.22초 | 황동 시계 극장. 새 배경, 회전 톱니 다섯 개와 거대한 진자, 시계 레일. 시소는 여기서 한 번만 사용. 첫 연타는 근접 화면에서 균열을 일으킨다. |
| 44.22–66.33초 | 22m 낙하와 침수 기록실. 수면 반사와 석판, 후반에는 플레이어 아래에서 함께 상승하는 수직 리프트. |
| 66.33–91.59초 | 보랏빛 거울 계단. 떠 있는 책 위를 왼쪽으로 두 구간 올라간 뒤 오른쪽으로 복귀한다. 카메라는 여러 층을 보여주며, 화살표와 채보의 쉼이 방향 전환을 예고한다. |
| 91.59–120.01초 | 어두운 별자리 길. 실선과 별로 이어진 공중 발판, 맥동하는 거대한 천체. 두 번째 연타에서는 문이 좌우로 열리고 카메라가 멀어진다. |
| 120.01–150.01초 | 새 하늘 배경, 떠다니는 소원 쪽지, 유리 발판과 리본 구조물. 마지막 연타는 날개가 펼쳐지는 넓은 종막 구도와 방사형 빛을 사용한다. |
| 150.01–168.997초 | 잔잔한 커튼콜. 느린 이동과 카메라 확장, 마지막 피아노 후 잔향까지 재생하고 결과 화면으로 이동. |

35개 경로 구간은 계속 연결된다. 네 번의 도약 중 시소는 한 번, 나머지는 스프링/별빛 궤적으로 구분한다. 원본 Stage1 판정·노트 이미지·HUD·메뉴는 유지한다. 미래 노트는 3.5초 이내의 것만 렌더링하여 역주행 중 다른 층의 채보가 화면을 채우지 않게 한다.

## 첫 연타 → 붕괴 → 입력 복귀 (2026-10-15)

- 첫 연타 약 41.067~44.225초: 매 입력에 바닥 균열의 밝기·두께와 발판 진동이 반응한다. 타격 이펙트는 첫 게이트에서만 작고 짧게 표시한다. 횟수나 완료 게이지는 표시하지 않는다.
- 약 44.225~47.382초: 22m 낙하 중 일반 판정을 요구하지 않는다. 카메라가 아래쪽 경로를 미리 보고, 금색 경로선과 착지 타원이 목적지를 안내한다. 붕괴 성공은 밝은 청록, 실패는 약한 황갈색의 국소 파동으로 구분하며 음악과 이동은 두 경우 모두 계속된다.
- 약 48.172초: 착지 두 박 뒤 첫 Tap을 판정한다. 안내선은 그 전에 사라진다. 30/60/144 FPS 및 16:9·4:3 카메라 시뮬레이션에서 첫 노트가 최소 1.2초 먼저 화면 여백 안으로 들어오는지 검사한다.
- 집중 검사: `BeatWave > Validate Stage3 - First Fracture`. 연타 성공/무입력 실패, 일시정지, 재시작 초기화, 착지 후 첫 세 Tap을 API 입력으로 검증한다. 실제 키보드 체감은 별도 플레이 확인이 필요하다.
- 기록: `Reports/Stage3-fracture-validation.txt`, 화면: `Docs/Preview/Stage3/Fracture-*.png`.
- 최종 검증: 집중 검사 전 항목 통과. 원곡 168.997초 전체 재생, 일반 274개와 Mash 3개 판정, 결과 집계 및 재시작·곡 선택·타이틀 전환 통과. 합성 입력 지연 Miss 0, 관측 오디오/DSP 차이 최대 21.3ms. 종료 후 컴파일 오류와 콘솔 오류 0건.

## 구성 파일

- `Scripts/Gameplay/Stage3Route.cs`: 전체 이동 경로, 수직 리프트와 좌우 전환, 일곱 막의 시간. 전체 폴더 역할은 `Assets/Stage3/README.md` 참고.
- `Stage3Gameplay.cs`: 노트 표시 범위, 방향 전환, 구간별 카메라 구도.
- `Stage3Scenography.cs`: 배경 교차 전환, 진자·톱니·수면·리프트·문·날개·쪽지의 음악 시각 기반 움직임.
- `Stage3SceneryBuilder.cs`: 장면별 무대 장치와 다섯 가지 신규 발판 형태.
- `Stage3SceneBuilder.cs`: 씬 재생성, 음원·판정·장면 연결.

## 음원과 재생성

`Assets/Stage3/Audio/LastWishOriginal.wav`는 사용자 제공 FLAC의 44,100 Hz / 스테레오 / 16-bit PCM 무손실 변환본이다. 소스 샘플 7,452,755개와 재디코딩 WAV의 완전 일치를 확인했다. Unity 샘플 수 표시는 한 샘플 반올림될 수 있다. WAV SHA-256: `67d9b6d35134dc131557c3f61d5e417450ec3514addc796e0ef20e20499c71da`.

채보는 프로젝트 루트에서 `python Tools/build_lastwish_chart.py`로 재생성한다. 씬은 저장 후 Play 모드를 종료하고 `BeatWave/Build Stage3 - Last Wish`를 실행한다. 이 메뉴는 변경 전 씬을 Reports에 백업한다.

검사 메뉴: `BeatWave/Validate Stage3 - Scene and Chart`, `BeatWave/Validate Stage3 - Full Original Playback`.
검사 결과: `Reports/Stage3-variety-validation.txt`. 실제 화면: `Docs/Preview/Stage3/Variety-*.png`.
자동 검증은 판정 API에 합성 입력을 넣고 홀드 종료 API를 호출한다. 실제 키보드 조작감과 사람이 느끼는 난이도를 평가한 검사는 아니다.
